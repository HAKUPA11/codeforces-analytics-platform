# Codeforces API Documentation

## Overview

The Codeforces API provides public access to contest, user, problem, and submission data through REST endpoints.

The API returns data in **JSON** format and, for most endpoints, does not require authentication.

This API will serve as the primary data source for the **Codeforces Analytics Platform**.

---

## Official Documentation

https://codeforces.com/apiHelp

---

All API requests follow the format:

```
https://codeforces.com/api/{methodName}
```


Examples:

```
https://codeforces.com/api/user.info?handles=tourist

https://codeforces.com/api/user.rating?handle=tourist

https://codeforces.com/api/user.status?handle=tourist

https://codeforces.com/api/contest.list

https://codeforces.com/api/problemset.problems
```

---

# Response Format

Every successful request returns:

```json
{
    "status": "OK",
    "result": [...]
}
```

If an error occurs:

```json
{
    "status": "FAILED",
    "comment": "Error message"
}
```

# API Endpoints Used in this Project

| Endpoint | Purpose | Database Table |
|----------|---------|----------------|
| `/user.info` | Fetch user profile | `users` |
| `/user.rating` | Rating history | `rating_history` |
| `/user.status` | User submissions | `submissions` |
| `/contest.list` | Contest information | `contests` |
| `/problemset.problems` | Problems and tags | `problems`, `problem_tags` |

---

# Endpoint 1 — `/user.info`

## Purpose

Returns profile information of one or more Codeforces users.

---

## Request

```
GET /user.info
```

---

## Required Parameter

| Parameter | Description |
|-----------|-------------|
| `handles` | One or more Codeforces usernames |

Example:

```
https://codeforces.com/api/user.info?handles=tourist
```

---

## Important Response Fields

| Field | Description | Store in Database |
|-------|-------------|------------------|
| handle | Username | ✅ |
| rank | Current rank | ✅ |
| rating | Current rating | ✅ |
| maxRank | Highest rank achieved | ✅ |
| maxRating | Highest rating achieved | ✅ |
| contribution | Contribution score | ✅ |
| friendOfCount | Number of followers | ✅ |
| organization | Organization/College | ✅ |
| country | Country | ✅ |
| city | City | ✅ |
| avatar | Profile image | ❌ |
| titlePhoto | Cover image | ❌ |

---

# Database Mapping

The following information will be stored inside the **users** table.

| Database Column | API Field |
|----------------|-----------|
| user_id | Internal Primary Key |
| handle | handle |
| rank | rank |
| rating | rating |
| max_rank | maxRank |
| max_rating | maxRating |
| contribution | contribution |
| friend_count | friendOfCount |
| organization | organization |
| country | country |
| city | city |
| last_updated | Timestamp generated by ETL |

---

# Why Some Fields Are Ignored

Fields such as **avatar** and **titlePhoto** are not required because this project focuses on **analytics**, not user profile rendering.

Storing unnecessary data increases storage requirements without providing analytical value.

---

# Analytics Opportunities

Using only the `/user.info` endpoint, the following analyses become possible:

- Highest-rated users
- Average rating by country
- Average rating by organization
- Rank distribution
- Country-wise user distribution
- Organization-wise performance
- Contribution analysis
- Top users by maximum rating

# Notes

- User profiles should be updated periodically.
- The `handle` field is unique for every Codeforces user.
- An internal integer `user_id` will be used as the primary key.
- API failures should be logged during ETL execution.
- Missing values should be handled before inserting into the database.
